# 04 - 剪贴板历史（第一个「插件形态」内置功能）

Status: done

## 需求

uTools 使用率最高的能力之一。记录复制历史，随时检索回贴。同时是 ZTool 第一个按插件接口实现的内置功能——内部抽象（面板视图贡献、生命周期、设置项）为后续插件运行时留缝。

## 已确认的设计决策

- **内容类型**：文本 + 图片（文件类二期）
- **持久化**：SQLite 单文件
- **容量**：默认 1000 条，淘汰最旧**未固定**项
- **固定/收藏**：钉住条目不参与淘汰，视图内置顶；存储从一开始留 `pinned` 字段
- **入口**：主面板 Tab 视图切换（搜索 / 剪贴板）为主 +「剪贴板」命令兜底；视图内搜索；**不加**独立全局热键
- **隐私**：「暂停记录」开关 + 可编辑进程排除名单（默认含 KeePass / 1Password / Bitwarden 等）；不做内容启发式检测
- **toggle 语义一致**：失焦 / Esc 关闭时剪贴板视图同步收起、清空

## 子项清单

- [x] 监听剪贴板（文本 + 图片），去重（连续相同内容合并为一条，刷新时间戳）
- [x] SQLite 存储：`content`（文本或图片路径）、`type`、`created_at`、`last_used_at`、`pinned`、`source_process`
- [x] 进程排除名单 + 暂停记录开关（开关状态持久化）
- [x] Tab 视图切换（搜索 / 剪贴板），「剪贴板」命令兜底进入
- [x] 剪贴板视图：搜索框、列表（文本摘要 / 图片缩略图）、↑↓ 选择、Enter 回贴并置顶刷新、固定/取消固定
- [x] 容量淘汰（跳过 pinned）+ 本地图片文件的孤儿清理
- [x] 按插件形态组织：定义 `IPanelPlugin`（或等价）内部接口——贡献视图、查询、激活动作；剪贴板功能只经此接口接入主面板

## 验收标准

- [x] 复制文本 / 截图后，面板剪贴板视图可见对应条目
- [x] Enter 回贴内容正确（文本原样、图片可用）
- [x] 淘汰 1000 条上限生效，固定条目永不淘汰
- [x] 暂停记录期间的复制不入库；排除名单进程的复制不入库
- [x] 重启应用后历史仍在（SQLite 持久化）
- [x] 连续复制相同内容不产生重复条目

## Comments

### 2026-10-17 — 实现

**结构**（审问 Q6/Q7/Q25/Q31/Q32）：

- `IPanelPlugin`（`Services/IPanelPlugin.cs`）= 视图贡献（`Rows(query)`）+ 生命周期（`Start`/`Stop`）+ 设置项（`Settings` 描述式）+ 键盘（`TryHandleKey`）+ 页脚控件槽（`Footer`）。
- **搜索自己也是一个 plugin**（`Services/SearchPlugin.cs`），把原来的 `AppIndex`/`FileIndex`/`CommandProvider`/`SearchService` 收了进去。缝是真缝——将来抽运行时只是把接口搬出去。
- `PanelRow`（`Models/PanelRow.cs`）是宿主唯一的行类型：标题 / 副标题 / 图标或字形 / 标记 / 激活动作。`SearchResult` 保留在搜索插件内部（拼音字段是搜索专属）。
- `SettingDescriptor` 是**描述式**（键/标签/类型/读写委托），给未来设置界面用；「暂停」这条设置项的读写就是它的实例。页脚那个开关只是它在 M1 唯一的落点，两者是两个独立成员。
- 插件专属键走 `TryHandleKey(activeRow, key, modifiers)`：宿主先跑 ↑↓/Enter/Esc，剩下的问当前激活的插件。`Ctrl+P` 固定、`Delete` 删除都在剪贴板插件里。

**行为决策**：

| 面 | 定论 |
|---|---|
| Enter 回贴 | 写剪贴板 → 还原呼出前的前台窗口 → `SendInput` Ctrl+V。注入失败（UIPI 挡了提权窗口）内容仍在剪贴板 |
| 视图切换 | `Ctrl+Tab` / `Ctrl+Shift+Tab`，meta 行显示当前视图名（查询框两个视图长得一样，只有这里说得出在哪） |
| 「剪贴板」命令 | 切视图、**不收面板**（它是 `Ctrl+Tab` 的等价物）；顺带清空查询框——那个查询是「剪贴板」三个字，带过去只会让人以为历史是空的 |
| 关闭后回到哪 | 空态**搜索**视图（01 立的「再次呼出 = 空态」把视图也一起算上） |
| 去重 | **全局**去重：已存在的内容合并到一条、移到顶、刷 `last_used_at`（比规格子项的「连续相同」宽，验收那条两者都满足） |
| 一次复制多格式 | 一条记录：有图片取图片，没有图片取纯文本。**CF_HDROP（复制文件）一条都不记**——也不偷偷新建路径文本，那会看起来像复制了词 |
| 搜索范围 | 全文（`content` + `preview`） |
| 容量 | 总数上限 1000，超了只从最旧**未固定**里淘汰；pin 多了实际条数会超过 1000 |
| 启动 | 收编当前剪贴板（登录自启时那是昨天最后复制的东西） |
| 面板开着时复制 | 即时插到顶部，但**选中项跟着原条目走**（被挤走是实打实的恼人） |
| 图片落盘 | PNG，单条上限 **2MB**（不是 8MB——1000×8MB 最坏 8GB）。1080p 截图约 200–500KB |
| 回贴后面板 | 收起（和搜索视图一致；连贴就再呼出） |
| 文本归一化 | **只削结尾**的 CRLF/空白（Windows 加的尾巴），正文一字不动 |
| 图片去重键 | **像素哈希**，不是文件字节（同一张图两种编码是一条） |
| 行的副标题 | 时间 + 来源进程都放（排查「这条哪来的」和排历史的新旧都用得上）；图片行加尺寸 |
| 排除名单 | `exclusions.txt`，一行一个进程名，每次复制时重读（改完立刻生效，不逼人重启） |
| 设置落点 | `settings.json`（标量）+ `exclusions.txt`（列表）+ `clipboard.db` + `images/`，全在 `%AppData%\ZTool\` |
| 一屏几条 | 剪贴板 12 条（`MaxHeight≈720`），搜索仍 7 条——翻历史和「第一行就对」是两种尺度 |
| 图标槽 | `KindMark` 位置；色块底衬保留（左缘节奏基准） |
| 行模型 | 新增 `PanelRow`，`SearchResult` 转成它，宿主只认 `PanelRow` |

| 验收 | 结果 |
|---|---|
| 复制文本/截图入库 | ✅ 文本、`PrintScreen` 真截图（2240×1400）都进 |

### ⚠️ 实现期发现并修掉的两个真 bug

1. **`bfOffBits` 写死成 14**。`PrintScreen` 出的是 `BI_BITFIELDS` 的 DIB，三块调色掩码跟在 `BITMAPINFOHEADER` 后面，像素起点是 `14+40+12=66`（`BITMAPV5HEADER` 则是 `14+124=138`）。写死 14 导致**真实截图一律解不开**——探针此前只测了自己造的 PNG，走不到这条路径。现已按 DIB 自己的 `biSize`/`biCompression`/`biBitCount` 算。
2. **`INPUT` 结构体是 32 字节而不是 40**。联合体要按最宽的 `MOUSEINPUT`（32 字节）算，`INPUT` = 4 + 4 + 32 = 40。尺寸错了 `SendInput` 直接 `ERROR_INVALID_PARAMETER` 且**无任何可见报错**，回贴退化成「内容进了剪贴板但没有 Ctrl+V」。探针现在断言 `Marshal.SizeOf<INPUT>() == 40` 并实调一次 `SendInput` 看返回值。

另外调研实测：**`PrintScreen` 不放 PNG**，只出 `CF_BITMAP`/`CF_DIB`/`CF_DIBV5`。读取优先级因此改成 `PNG → CF_DIBV5 → CF_DIB`。

### ⚠️ 已知限制（试用期留意）

1. **来源进程归属是启发式，不是审计。** `GetClipboardOwner()` 在实测里基本恒为 NULL（拷贝方的临时窗口已经销毁），代码退到 `GetForegroundWindow()`。因此：后台程序主动写剪贴板会归属错、拷完立刻 `Alt+Tab` 会归属错、`PrintScreen` 这类系统级复制没有真实来源。**排除名单是「尽力而为」，不是精确审计。** 若试用期发现误杀/漏杀，改法是改成「拷贝前的前台快照」而不是「捕获时的前台」。
2. **`SendInput` 遇提权窗口静默失败**（UIPI）。按 Q1-a 的设计，内容仍在剪贴板上，手贴一步即可；不弹框。
3. **终端类应用**（Windows Terminal 等）部分绑定 `Ctrl+Shift+V` / `Shift+Insert` 而非 `Ctrl+V`。目前只发 `Ctrl+V`，若试用期在终端里贴不出来，加 `Shift+Insert` 兜底即可。
4. **图片行的检索靠尺寸**（`preview` = `2240×1400`）。图片没有正文，输入文字搜不到它是预期行为。
5. 图片按像素去重，解码一次哈希；超大图会被 2MB 上限挡在门外，不记录。

### 与审问结论的两处小偏差（已落，留档）

- 固定标记用了 **★** 而不是图钉字符：BMP 里没有好用的单色图钉字形，emoji 又会破坏「安静」的调性。★ 渲染稳定、语义通用。要换随时可换。
- 「重新索引」命令改成**执行后面板不收起**（原来会收）。理由是这条命令的价值就在 meta 行那句「正在索引…」，收起就看不见了。和「剪贴板」命令同属「换场景」而非「离开」。
