# 02 - Store/AppX 应用索引

Status: done

## 问题

Win10 的记事本 / 画图 / 计算器等系统应用是 Store（AppX）版，开始菜单里没有 `.lnk`，当前 `.lnk / .appref-ms / .exe` 扫描覆盖不到——搜「记事本」返回无结果。2026-10-16 实测确认（Chrome 等传统应用正常）。

## 修法

AppIndex 补充 AppX / AppsFolder 枚举（如 `IApplicationActivationManager` / 开始菜单 `appsFolder` 或 PowerShell `Get-StartApps` 对应的 Win32 枚举），把 Store 应用的 AUMID 纳入索引，Enter 启动走 AUMID 激活。

## 验收标准

- [ ] 「记事本」「画图」「计算器」可搜可启动
- [ ] Store 应用与传统应用在结果中混合排序、图标正确
- [ ] 已有 `.lnk/.appref-ms/.exe` 行为不回归（Chrome 对照）
- [ ] 重复索引（重新索引命令）后无重复条目

## Comments

### 2026-10-17 — 实现

**选型**（审问轮次 Q2/Q3/Q5/Q6/Q7/Q23/Q24/Q30）：

- 枚举：`Shell.Application` 的 `shell:AppsFolder` 命名空间，IDispatch 逐条取 `Name` / `Path`（即 AUMID 或解析名）。落点是 `AppIndex.Rebuild()` 内追加一段，不新建 provider——`SearchService` 不跨 provider 去重，两条名单放在同一处共用 `seen` 集合最省事。
- 启动：`IApplicationActivationManager.ActivateApplication(AUMID, …, NoErrorUI)`（`Services/AppActivation.cs`），失败退回 `shell:AppsFolder\<id>`；非包条目走 `AppsFolder.ParsingName(id)`（真路径直接开，解析名走 folder moniker）。`{1AC14E77-…}\notepad.exe` 这类 KNFID 解析名**不是路径**，直接 `Process.Start` 会失败——这是实现期才发现的。
- 去重：Start Menu 先扫先得，AppsFolder 只补名字没被占用的（Q3-c）。
- AppsFolder 内部同名冲突按 id 的「身份份量」排序：包 AUMID > 普通路径/解析名 > `Microsoft.AutoGenerated.*`。本机 `设置` 在 AppsFolder 里有 shell 生成的替身和真正的 `windows.immersivecontrolpanel_…`，没有这条规则会拿错。
- 噪声：AppsFolder 的 shell 组件按包族名精确排除（`Microsoft.Windows.ShellExperienceHost` 等，**不含** `windows.immersivecontrolpanel`——那是「设置」）；`.url/.html/.htm/.chm/.pdf` 这类文档目标整类跳过；显示名关键词沿用并扩充 `Noise`（`manual/手册/文档/release notes/faq/website/网站/入门/教程/tutorial`）。实测 325 → 294 条。
- 副标题：发布者（`AppxManifest.xml` 的 `PublisherDisplayName`，退到 `Identity Publisher` 的 `CN=` 主体）。`ms-resource:` 这类未解析的资源占位串一律丢弃不显示。

**实测**（`.scratch/appsfolder-probe/`，可复跑：`dotnet run` / `dotnet run -- --launch`）：

| 验收 | 结果 |
|---|---|
| 记事本 / 画图 / 计算器 可搜可启动 | ✅ 搜索见上；**真启动验证**：`Launch()` 后 `notepad` / `mspaint` / `CalculatorApp` 三个进程都起来了（Q4 定的真启动），验证后已关闭 |
| 混合排序 | ✅ 322 条索引里 AppsFolder 与 Start Menu 条目同列表 |
| 图标正确 | ✅ 见 05，322/322 拿到位图 |
| Chrome 不回归 | ✅ `chrome`→Google Chrome，仍走原有 `.lnk` 路径 |
| 重新索引无重复 | ✅ `Rebuild()` 整体替换列表，按 title 分组无重复 |

`Rebuild()` 在后台线程（`Task.Run`）跑完整流程、位图也能建——这一点单独验过，因为 `WriteableBitmap` 在非 UI 线程创建是运行期才见分晓的。

注：本机实况与 issue 原文略有出入——记事本 / 画图 是 `{1AC14E77-…}\notepad.exe` / `mspaint.exe` 这类 Win32 系统项（不是包），计算器才是包。三者都没有开始菜单 `.lnk`，所以 AppsFolder 确实是唯一来源，问题本身成立。

**附带（Q31-a 并入本 issue）：首次索引的加载动画。** 02 让 `Rebuild()` 变重了（AppsFolder 枚举 + 图标提取），启动后台重建的空窗期需要一个交代。

- 形态（Q33-c）：面板底缘一条 2px 不定长 Signal 横条（`ProgressBar.IsIndeterminate`），meta 行同时显示「正在索引…」。Signal 是配色里唯一「活着」的语义色，拿它做进度条零成本。底缘覆层不改变 `SizeToContent` 高度——把查询框下那条发丝发隔线换成 2px 横条会让窗口跳 1–2px。为此 slab 多包了一层 `ClipToBounds` 内框，把横条裁进圆角；阴影留在外框，裁剪吞不掉。
- 时机（Q26-a）：**只在启动的首次 `WarmUp()` 显示**，重建完即消失。手动「重新索引」不显示动画——那时旧列表还能看，用动画盖掉是倒退。`MainViewModel.WarmUp()` / `RebuildIndex()` 分别走 `Rebuild(indicateProgress: true/false)`。
- 呼出（Q25-a）：索引没热完也允许呼出，列表暂空，热键必须即时响应。01 刚修过「按了没反应」这类体验问题，把呼出挂起是重蹈覆辙。

**遗留 · 名字撞车**：「设置」这个名字被搜狗输入法的开始菜单快捷方式占了（`G:\SogouInput\SogouExe`），按 Q3-c「Start Menu 先到先得」Windows 自带设置就被挡在外面了。于是搜 `设置` 出来的是搜狗设置，`sz` 里也看不到 Windows 设置。

这是 Q3-c 没覆盖到的一格：该决策针对的是**同一个应用**别在两处出现（Chrome 对照），不是**两个不同应用**撞名。本机就撞了。可选修法（未做，等定夺）：

- (a) 维持现状——搜狗设置也是用户装的，能打开就行
- (b) 撞名时优先保留包 AUMID（`windows.immersivecontrolpanel_…`），`.lnk` 只在没有包同名时才占位
- (c) 撞名时两条都留，靠副标题区分（「G:\SogouInput\SogouExe」vs「Microsoft Corporation」）

(b) 最省事，但会把 Q3-c 的「Start Menu 优先」改成「包优先」，Chrome 这类既有条目不受影响（它的 AppsFolder id 不是包 AUMID）。影响面只在撞名场景。
